# Platform integration requirements

Research checked September 11, 2026. Software capacity is not platform permission. Current developer access, account authorizations, content rights and quotas must be verified before enabling any live integration.

| Platform | This release | Requirements and operational implications |
|---|---|---|
| YouTube | Direct private-upload worker adapter; provider calls tested with fixtures only | OAuth user consent, `youtube.upload` plus `youtube.readonly` for channel verification, matching registered channel ID, quota and any required audit. New unverified projects are restricted to private uploads. The worker refreshes access tokens and records the returned video ID. [Upload API](https://developers.google.com/youtube/v3/docs/videos/insert), [resumable protocol](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol). |
| Instagram | Manual media and metadata handoff | Professional account and approved Meta app permissions. Consumer accounts are not supported by the professional publishing API. A container/status/publish adapter and approved OAuth onboarding remain to be implemented. [Meta's official Instagram collection](https://www.postman.com/meta/instagram/folder/6raa77c/instagram-api-with-instagram-login). |
| Threads | Manual media and metadata handoff | Threads OAuth, `threads_basic`, `threads_content_publish` and live account publishing-limit checks. A container/status/publish adapter and approved OAuth onboarding remain to be implemented. [Meta's official Threads collection](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api). |
| X | Manual media and metadata handoff | Approved developer access, user authorization and account-specific limits. Distinct purposes and nonduplicative content are required. Automated amplification among controlled accounts is prohibited, and AI reply bots require prior written approval. [Authenticity policy](https://help.x.com/en/rules-and-policies/authenticity), [automation rules](https://help.x.com/en/rules-and-policies/x-automation). |
| TikTok | Manual creator review and upload | Direct Post guidelines explicitly disallow an internal tool for accounts managed by your team and arbitrary copying from other platforms. Required creator preview, consent and privacy choices cannot be replaced by unattended bulk automation. Unaudited apps face private-visibility and creator restrictions. [Content-sharing guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines). |
| Snapchat | Manual media and metadata handoff | Public Profile API is allowlist-only, with Snap business setup, OAuth and creator authorization. An approved Story/Spotlight publishing adapter remains to be implemented. [Public Profile API setup](https://developers.snap.com/marketing-api/Public-Profile-API/GetStarted). |

YouTube's September 2026 quota documentation describes default daily allocations of 100 `videos.insert` calls, 100 `search.list` calls and 10,000 units for other endpoints. Higher quota requires the relevant compliance process. Do not size a 10,000-account operation from these default project limits. [YouTube quota and compliance audits](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits).

Streamer footage, sports footage, music and recordings need documented authorization for the intended use. A rights attestation is an operator record, not automated legal clearance. YouTube's reused-content monetization rules are separate from permission to use the media. The system does not claim monetization eligibility or guaranteed reach. [YouTube rights requirements](https://support.google.com/youtube/answer/2490020), [monetization policies](https://support.google.com/youtubecreatorstudio/answer/1311392).

There is deliberately no automatic liking, viewing, following, commenting or cross-account reply network. YouTube prohibits artificial engagement, and X prohibits coordinated account amplification. [YouTube fake engagement policy](https://support.google.com/youtube/answer/3399767), [X authenticity policy](https://help.x.com/en/rules-and-policies/authenticity).
